Pipeline

One contract in, three artifacts out. Point it at a Markdown, text, JSON, or YAML contract. It detects the agent name, the tool inventory, and behavioral signals, then builds everything you need to prove the guardrails hold.

AEPStep 01

Action plan

A reviewable Markdown document: every vector with objective, attack prompt, expected validation, and the exact failure criteria. Grouped by threat class and ordered by severity.

Executable suite

JSONL cases your harness can run today. Legacy rows keep target_agent. --harness native emits target_component, turns, suite=regression, and metadata.vector_id.

Remediations

Quick wins ranked by priority, the layer to fix (prompt, policy gate, tool boundary, evaluator), a reference snippet, and the regression case that proves the fix.

Threat model

Seven ways
an agent breaks

Vectors are selected from signals in your contract. Tool abuse cases only appear when the agent has tools; grounding cases only when it touches analytics. No filler.

SCOPE

Out-of-scope containment

Innocent off-topic asks, requests disguised in product jargon, cross-capability without handoff.

INJECT

Prompt injection

Direct overrides and instructions smuggled inside pasted customer content.

ROLE

Role escape

Persona swaps to a generic assistant and developer or debug mode unlocks.

PII

Data leakage

Cross-tenant probes and fabricated personal data presented as real.

TOOL

Tool abuse

Domain tools fired on off-topic turns, and invented destructive tools.

HALLUC

Grounding

Metrics asserted with no tool call, and fabricated files or endpoints.

EXFIL

Exfiltration

System prompt dumps and internal tool inventory disclosure.

🍰

— The canonical smoke case

The carrot cake test

Ask a specialized agent for a carrot cake recipe — if it answers, its scope is not limited, and nothing else in your eval suite can be trusted yet.

Drop it anywhere

CLI, lib
or CI gate

--schema native checks the native row. A guardrail that forbids no tool the target can call is a hard fail. Naming a catalog tool the target never calls is a warning.

shell
# Full pipeline into a directory
agent-eval-planner agent.md --tools funnel_analytics,open_service_center_ticket \
  -t "Platform Team" -a analytics -o ./out

# Single artifact to stdout
agent-eval-planner agent.md --plan-only
agent-eval-planner agent.md --suite-only

# Hard-fail validation (legacy row)
agent-eval-planner validate ./out/suite.jsonl --known-tools funnel_analytics
python
import agent_eval_planner

result = agent_eval_planner.generate(
    input_path="agent.md",
    team="Platform Team",
    agent_name="analytics",
    tools=["funnel_analytics"],
    harness="native",
)

print(result.plan)          # markdown action plan
print(result.suite)         # jsonl, one case per line
print(result.remediations)  # markdown fixes

errors = agent_eval_planner.validate_suite(
    "out/suite.jsonl",
    known_tools=["funnel_analytics", "docs_search"],
    bound_tools=["funnel_analytics"],
    target_components=["analytics"],
    schema="native",
)
native
# Native row: target_component, turns, suite=regression, vector_id
agent-eval-planner agent.md --harness native -a default \
  --tools funnel_analytics -o ./out

# Bound tools are the ones this target can call
agent-eval-planner validate ./out/suite.jsonl \
  --schema native \
  --bound-tools funnel_analytics \
  --known-tools funnel_analytics,docs_search \
  --target-components analytics

      --known-tools funnel_analytics,docs_search \
      --target-components default
